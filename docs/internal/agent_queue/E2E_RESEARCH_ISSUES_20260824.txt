PRODUCT-009 - Successful Codex response is masked by temporary plugin-cache cleanup race
Status: FIXED (commit eb79c70b8; live route verified in r6)
Observed in: qq-tech-trends-e2e-20260824-r5
Evidence:
- Codex produced response.json in 58 seconds, proving the UTF-8 request reached
  the signed-in model and returned structured output.
- TemporaryDirectory teardown then raised WinError 145 (directory not empty)
  under home/plugins/cache/.../tests/fixtures.

  evidence_synthesis evaluation_error.

  never displayed or logged; the exact run-owned file was immediately deleted

PRODUCT-013 - Report heading deduplication duplicates every nested subsection
Status: FIXED (pending commit)
Observed in: qq-tech-trends-e2e-20260824-r8
Evidence: the final reviewer found that all nine `###` technology-trend
subsections appeared twice in the deliverable Markdown, even though the model's
structured `sections` field contained only one technology-trend section. The
revision then incorrectly claimed that the duplicates had been removed.
Root cause: `_dedupe_repeated_heading_sections` appends the complete range of a
parent `##` section, including all nested headings, and subsequently appends
each nested `###` range again while walking the same heading list.

acceptance even when the provider returned only one copy.

ranges so a repeated parent safely removes its subtree without reconstructing
or duplicating the first copy.

research service suite passed (29 passed in 2.03s).

PRODUCT-014 - Claim grounding treats substantive Chinese claims as empty text
Status: FIXED (pending commit)

two-character CJK terms, while retaining its existing ASCII, number, scope,
and minimum-coverage checks.

evidence-synthesis regression passed (7 passed in 0.69s). The regression also
confirmed that unrelated Chinese claims and unsupported years still fail

PRODUCT-018 - Traceable conclusions create a second Conclusions heading
Status: FIXED (pending commit and live E2E verification)
Observed in: qq-tech-trends-e2e-20260824-r12 acceptance review
Evidence: final Markdown contained both `## 七、结论` from the provider body and
an auto-generated `## 结论` containing the evidence-linked structured
conclusions. References correctly remained last, but the conclusion section was
duplicated.
Root cause: `_normalize_report` checks whether each structured conclusion text
appears verbatim. When it does not, it always creates a new Conclusions section,
even if the body already has a semantically identical numbered Conclusions
heading. The heading deduper runs earlier, before this generated section exists.
Impact: the report preserves traceability but presents two conclusion sections.
Fix: merge missing evidence-linked conclusion bullets into the existing
Conclusions/结论/总结 section before its next peer heading; create a new section
only when none exists.

production research service tests passed (32 passed in 2.02s).
