PRODUCT-004 - Production resume recompiles an invalid, different task
Status: FIXED (pending commit)
Observed in: qq-tech-trends-e2e-20260824-r2 resume
Evidence:
- Exit code: 2
- Final status: failed
- Error: task contract violates frozen Phase 0 schema: seed_inputs.0:
  'artifact_ref' is a required property
- Resume classification changed workflow_kind from the persisted
  research_synthesis route to scientific_lifecycle.
Root cause: the control plane represents resume as a new external_evidence seed
with value resume:<run-id> and no artifact_ref. The runtime then recompiles a
new task and route before loading the existing run state.
Impact: an authorization-gated production run cannot be resumed, even when its
state and original task contract are valid and present.
Fix: resume now loads the persisted task contract, requires exact prompt and
workflow identity agreement, reuses the original seeds and route, and leaves
the frozen contract unchanged. The bridge no longer manufactures a fake
resume-state seed or overrides the persisted route with its generic resume
classification.
Regression tests:
- tests/repairs/research_control_plane/test_research_control_plane.py::test_research_cli_resume_reuses_persisted_task_and_route
- tests/harness/research_orchestration/test_research_production_runtime.py::test_runtime_resume_reuses_completed_state_without_redispatch
- tests/harness/research_orchestration/test_research_production_runtime.py::test_runtime_resume_rejects_prompt_different_from_persisted_contract
Verification:
- Focused runtime tests: 2 passed in 2.55s
- Bridge plus runtime resume tests: 3 passed in 6.82s
- Broader related suites: 21 passed and 4 independent failures in 77.74s.
  Those failures are recorded below as PRODUCT-005 and TEST-002.
