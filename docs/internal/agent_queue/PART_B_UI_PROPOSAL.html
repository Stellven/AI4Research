Why this is the right diagram. It is a real provenance chain with real hashes, not a drawn pipeline — so it does not violate DESIGN.md’s “no fake linear flow/arrows”. It is the only view that makes the Part A → Part B bridge visible, and it is exactly where a tamper or a silent substitution would show up.

Recommendation

ApproachVerdict
“All experiments” diagramWould be dishonest — there is exactly one experiment by contract. Drawing a field of parallel experiments implies capability that does not exist.
AutoSci Cytoscape graphWrong instrument. It is a citation/knowledge graph over papers and concepts, and it loads from CDN, which breaks the network-disabled container UAT.
Lifecycle roster alone (A)Necessary, not sufficient. Shows a score, never the substance.
Roster + lineage (B)Recommended. Adds the one view that proves the evidence claim, using data the run already writes.

If Part B ever gains real multiplicity

If the contract later allows several experiments, the honest extension is to repeat the lineage panel per experiment under its own heading — not to draw a graph of experiments. Multiplicity should be shown by repetition of a truthful unit, not by a new abstraction.
